## How to write it
- Output Markdown for the body of the section only. Start with the H2 line (`## heading`, exactly the planned heading). Use H3 for the planned subheadings and H4 only when a subsection truly needs it. Never output an H1.
- Reach the target length: at least ninety percent of `target_words` and not more than one hundred and thirty percent. Reach it with substance (explanation, reasoning, examples, steps, trade-offs, mistakes, edge cases), never with filler or restating.
- If the section has a `direct_answer_question`, use it as the first subheading or the opening line and give the direct answer in 40 to 80 words before the depth.
- Follow the `format`. A table is Markdown with a header row. A list is used only where the content is list-shaped. Most of the section stays prose.
- Links: write Markdown links `[anchor](address)` using only the addresses given in the links list. No other links. Do not invent URLs, sources, statistics, studies, quotes, prices or customer stories. Where a point would need an authoritative source you were not given, phrase it as general, unnumbered knowledge or leave it out, and add it to `open_claims`.
- Do not repeat what earlier sections already said; build on it. Do not write the introduction again unless this is the introduction, and do not write a conclusion unless this is the last section.
- `summary` is two sentences describing what this section established, for the writer of the next sections. `open_claims` lists any statements that still need a verified source before publishing (possibly empty).
