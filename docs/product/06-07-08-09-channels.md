# Modules: SMS and voice, email, WhatsApp, Meta channels
Status: draft   Owner: Ahmad   Phases: 3, 5, 6   Source: ghl-spec sections 7 to 10; ADR 0010

Each channel is one adapter behind the `ChannelAdapter` port with a contract test suite and a fake. Jurisdiction rules are data (law profiles), default Canada (CASL, PIPEDA). All sends use the gateway.

## Email (phase 3)
Sending domains with generated and verified DNS (SPF, DKIM, DMARC, return path); inbound parse and threading; bounces, complaints and suppression; one-click unsubscribe; campaigns with batch drip and A/B test.
Acceptance: a hard bounce suppresses the address and blocks later sends with reason `suppressed`; unsubscribe writes one consent row.

## SMS and voice (phase 5)
CPaaS port (Twilio first); numbers; segment and cost counter (GSM-7 and UCS-2); STOP, START, HELP through the consent ledger; click to call, recording, voicemail, missed-call text-back; sender registration as data-driven wizards.
Acceptance: STOP sets sms opt-out and sends the confirmation once; a send to an opted-out contact never reaches the adapter.

## WhatsApp (phase 6)
Official Cloud API only; embedded signup; per contact and number 24 hour window; template manager with approval sync; versioned rate cards by country and category.
Acceptance: outside the window the composer allows templates only and the gateway blocks free text with reason `window_closed`.

## Messenger, Instagram, lead ads, CAPI (phase 6)
Reuse the existing `/meta` connection layer and the Instagram module through the bridge. Lead ads map form fields to contacts with attribution; Conversions API events send only with consent and configured rules.
Acceptance: a lead ad webhook delivered twice creates one contact and one activity.

## Open questions
Provider choice and costs per channel; local SMS aggregators for markets without A2P.
